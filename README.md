# Редактор OUTMAX / ХАСЛ 2.0

Версия 2.0 объединяет обновлённые редакторы статей OUTMAX и ХАСЛ с самостоятельным редактором email-рассылок. В редакторе статей доступны WYSIWYG-холст, перетаскивание смысловых блоков, расширенное форматирование, редактируемые таблицы, изображения, CTA-кнопки и аккуратный импорт материалов без принудительной пересборки исходного дизайна.

## Редактор статей ХАСЛ

В проект добавлен второй самостоятельный режим для **хасл.рф** и **haslestore.com**. Запустите `Редактор ХАСЛ.bat` или откройте `http://127.0.0.1:8765/hasl/` после обычного запуска. Редактор использует отдельные черновики, фирменное оформление ХАСЛ, загружает товары по артикулу или полной ссылке и экспортирует HTML/ZIP для русского, международного либо сразу обоих доменов. Переключиться между редакторами OUTMAX и ХАСЛ можно из меню в шапке.

В проекте также есть отдельный **Редактор email-рассылок OUTMAX / ХАСЛ**. Запустите `Редактор EMAIL OUTMAX.bat`, откройте `http://127.0.0.1:8765/email/` или перейдите в него кнопкой в верхней панели редактора статей. Он импортирует готовые HTML, ZIP и RAR и сохраняет структуру и характер исходного дизайна, включая карточки товаров, галереи, оглавление и сравнения. Слева отображается веточная структура письма: разделы, товарные карточки и элементы сравнения можно выбирать, удалять, переставлять стрелками или перетаскивать за маркер `⠿`; выбранный блок также можно перенести непосредственно на холсте. При экспорте несовместимые с Gmail, Яндексом, Mail.ru и Outlook конструкции преобразуются в устойчивые email-таблицы: галереи показываются в две колонки на компьютере и по одной фотографии на телефоне, а широкие сравнения — компактными карточками с подписями показателей. Мобильные письма используют боковые поля `12 px`, уменьшенные заголовки и компактные сетки. Оглавление выводится аккуратными строками, товарные карточки получают безопасные внутренние отступы, а ссылки действий — отдельные кнопки. Готовый блок заранее приведён к белому списку NotiSend: служебные атрибуты редактора не попадают в экспорт, а ключевой дизайн записан inline. Редактор, готовый HTML и предпросмотр вынесены в отдельные режимы; в предпросмотре рядом показаны десктоп с максимальной шириной 700 px и телефон. Изображения загружаются по мере просмотра через локальный кеш, поэтому большие подборки не создают десятки одновременных запросов. Перед копированием или сохранением нужно выбрать OUTMAXSHOP.ru, OUTMAXSHOP.com, хасл.рф либо haslestore.com — ссылки и пути изображений становятся полными и получают выбранный домен. Для RAR на компьютере или сервере должен быть доступен UnRAR, 7-Zip либо bsdtar.

Email Studio интегрирован с NotiSend через серверный API: доступны реальные группы и статистика Campaigns, тестовая SMTP-отправка, preflight, автоматические UTM и создание Campaign-черновика. Email-проекты сохраняются отдельно для каждого пользователя вместе с локальными изображениями и настройками рассылки; после первого ручного сохранения изменения сохраняются автоматически. Созданный Campaign ID сохраняется в проекте, а повторное создание защищено дополнительным подтверждением.

Для согласования у сохранённого email-проекта можно создать публичную ссылку без входа в редактор. Получатель видит email в read-only preview и может переключать «Десктоп / Телефон»; ссылку можно отозвать. Внутренний workflow поддерживает статусы «Черновик», «На проверке», «Одобрено», «Нужны правки» и «В NotiSend». Модератор и администратор видят очередь согласования, открывают тот же публичный preview, оставляют комментарий и одобряют либо возвращают письмо на доработку. После содержательного изменения прежнее согласование автоматически сбрасывается. Системный footer с причиной получения письма и `[%unsubscribe_link%]` добавляется автоматически; в Campaign маркер сохраняется, а в SMTP-тесте и публичном preview ссылка безопасно нейтрализуется.

Запуск в Windows: откройте `Редактор OUTMAX.bat` (или `editor.bat`). Пункты меню: **1** — запустить редактор статей и email-редактор, **2** — сделать коммит и пуш в [GitHub](https://github.com/divangames/blogEditor), **3** — обновить [GitHub Pages](https://divangames.github.io/blogEditor/) из уже отправленного кода, **4** — отправить код в GitHub, обновить оба редактора на рабочем VPS и GitHub Pages, **5–8** — собрать пакеты для разных вариантов размещения, **9** — сразу обновить оба редактора на VPS. Пункт 9 использует ограниченный SSH-ключ из локальной папки `.deploy`, не хранит пароль VPS, проверяет адреса `/` и `/email/` после обновления и сохраняет серверную папку `articles`. Меню автоматически разрешает Git работать с текущей папкой, даже если Windows показывает другого владельца каталога. Если вход GitHub устарел, пункты 2–4 откроют браузер для повторной авторизации и продолжат работу после подтверждения. Батник использует английские надписи для совместимости с `cmd.exe`. Если редактор уже работает, пункт 1 откроет его вкладку. Папка `articles/` с черновиками не публикуется в GitHub и не перезаписывается при обновлении VPS. Или в PowerShell выполните `python -m pip install -r requirements.txt`, затем `python app.py`. После запуска откройте `http://127.0.0.1:8765` или `http://127.0.0.1:8765/email/`.

Для полноценного размещения без отдельной главной страницы в BAT доступны пункты **6** — пакет VPS/Docker, **7** — пакет Python WSGI/Passenger и **8** — сразу оба пакета. Результаты создаются в `release/outmax-editor-docker(.zip)` и `release/outmax-editor-python-hosting(.zip)`. Оба варианта открывают редактор непосредственно по адресу `/`, поддерживают серверные черновики, изображения, импорт товаров и статей, а также защищены сгенерированным логином и паролем. Учётные данные выводятся после сборки и записываются в инструкции внутри пакета.

Стабильные учётные данные рабочего редактора хранятся локально в `release/.outmax-deploy-credentials.json`; папка `release/` исключена из Git. При сборке они копируются в `release/outmax-editor-python-hosting/deploy_settings.py` и в настройки Docker-пакета. Сервер сначала читает переменные окружения `OUTMAX_USER` и `OUTMAX_PASSWORD`, а при их отсутствии — `deploy_settings.py`. Не добавляйте эти файлы и значения в репозиторий.

Основной рабочий адрес — `https://news.outmax-office.ru/`. Редактор ХАСЛ доступен по адресу `https://news.outmax-office.ru/hasl/`, а email-редактор — через переключатель в шапке или по адресу `https://news.outmax-office.ru/email/`. Прямой адрес `https://213.139.209.107/` сохранён как второй рабочий вход на тот же VPS и использует отдельный сертификат.

Для `news.outmax-office.ru` и `213.139.209.107` настроены отдельные сертификаты Let's Encrypt и отдельные HTTPS-виртуальные хосты Nginx. HTTP-запросы перенаправляются на HTTPS. Сертификаты автоматически продлеваются серверным таймером Certbot; проверка продления для домена выполнена успешно. Добавление домена не меняет приложение, общие черновики, изображения или Basic Auth: оба адреса открывают один экземпляр редактора с одинаковыми учётными данными.

Стандартный VPS-деплой публикует email-редактор через постоянный защищённый маршрут статических материалов, поэтому он обновляется даже без ручного перезапуска старого серверного процесса. VPS автоматически получает товары и статьи OUTMAX, хранит общие черновики и изображения и формирует экспортные HTML/ZIP. Статическая браузерная сборка в `docs/editor/` остаётся резервным вариантом.

На широком экране левое меню и полотно статьи прокручиваются независимо. Заголовок редактора, вкладки и инструменты форматирования остаются видимыми. Превью и HTML-код прокручиваются внутри своих областей.

В поле «Товары» можно вставить несколько артикулов или ссылок через запятую или с новой строки. Поддерживаются карточки `outmaxshop.ru` и `outmaxshop.com`; для артикула без полной ссылки домен выбирается над полем ввода. Одинаковые товарные пути на `.ru` и `.com` распознаются как один товар. Карточки загружаются в боковую панель с миниатюрой и названием. Их можно перетащить на холст или вставить кнопкой. Таблица сравнения создаёт строку с миниатюрой для каждого загруженного товара и заполняет до трёх критериев подтверждёнными свойствами карточек. «Не указано» означает отсутствие сведений, а не отсутствие свойства; критерии и значения можно править вручную. При выборе ячейки таблицы доступны добавление и удаление строк и столбцов. Свои изображения можно загрузить кнопкой. «Сохранить» создаёт `articles/<название>.html`, `articles/<название>.json` и папку `articles/<название>_files` для загруженных изображений. Список товаров сохраняется в JSON и восстанавливается при открытии ZIP.

Чтобы выбрать фото товара в таблице, нажмите на миниатюру или на строку модели и затем «Выбрать фото товара». Редактор показывает кадры из галереи соответствующего товара; можно также вставить прямую HTTPS-ссылку на изображение. Выбор меняет только эту строку таблицы и сохраняется в HTML без загрузки фото на компьютер.

В панели «Содержание и разделы» можно добавлять, переименовывать, переставлять и удалять разделы, задавать им якоря. Для каждого пункта содержания можно изменить текст и выбрать цель среди разделов и товаров, вставленных в статью.

В панели «Блоки и медиа» доступна кнопка с произвольным текстом в трёх вариантах: красная, чёрная и белая с чёрной рамкой. Кнопка может вести на внешнюю ссылку или на якорь текущей статьи. Внешняя ссылка по умолчанию открывается в новом окне; для якоря эта настройка отключается автоматически.

Обычно фото с `outmaxshop.ru` и `outmaxshop.com` используются по прямым URL. Изображения с других сайтов при сохранении автоматически скачиваются в папку ресурсов и включаются в экспортный ZIP; недоступные или неподдерживаемые файлы остаются по исходному адресу с предупреждением. Галочка экспорта «Создать локальную папку с изображениями» скачивает в `image/<название статьи>` только редакционные изображения статьи и меняет их HTML-пути на адреса от корня сайта. Фотографии карточек товаров и миниатюры сравнительных таблиц остаются прямыми ссылками OUTMAX и не увеличивают архив. Щелчок по элементу статьи открывает панель удаления; у заголовка раздела можно скрыть или вернуть линию. Двойной щелчок по изображению открывает настройки кадрирования, размера, выравнивания, alt и замены файла.

Чтобы продолжить писать вне изображения, товара, таблицы или другого блока, щёлкните в свободной области холста либо выберите блок и нажмите «Текст выше» или «Текст ниже». Редактор создаст отдельный абзац и поставит в него курсор.

Для вставки раздела, товара, таблицы или изображения наведите курсор на нужный промежуток в статье и нажмите «Вставить сюда» на красной линии. Затем используйте кнопку добавления слева: новый блок появится в выбранном месте. Кнопки раздела, содержания, выделенного блока и таблицы, а также товар из панели можно перетащить прямо на нужную позицию. Чтобы переставить уже вставленный блок, выберите его и перетащите за кнопку «Перетащить блок» на новое место.

«Открыть статью (HTML/ZIP)» загружает локальный `.html`, `.htm`, JSON черновика или ZIP с HTML и папкой изображений. Для распакованного публикационного комплекта используйте «Открыть папку статьи с фото»: редактор сам выбирает HTML, находит относительные пути вроде `assets/images/...`, загружает использованные изображения и включает их в будущий ZIP. Обычный публикационный HTML автоматически адаптируется: редактор распознаёт разделы, содержание, товарные карточки, галереи и кнопки. «Адаптировать статью» можно использовать повторно для ручной перестройки уже открытого материала.

«Загрузить статью без изменений» принимает адреса `outmaxshop.ru/article/…`, `outmaxshop.com/article/…`, `хасл.рф/news/…` и `haslestore.com/news/…`; `https://` можно не вводить. Редактор загружает только содержимое статьи без меню сайта и сохраняет исходные тексты, порядок блоков, заголовки, ссылки, таблицы, фото и безопасные inline-стили. Автоматическая пересборка разделов, оглавления, цен и рейтингов при импорте по ссылке не выполняется. Потенциально опасные сценарии, формы и служебные теги сайта не переносятся; видимый текст из их оболочек сохраняется. Импортированная статья остаётся черновиком до нажатия «Сохранить». Кнопка «Адаптировать статью» остаётся отдельной ручной командой.

Кнопка «Экспорт HTML / ZIP» предлагает подготовить ссылки для `outmaxshop.ru`, `outmaxshop.com` или сразу для обоих сайтов. В последнем случае ZIP содержит два HTML-файла с одинаковым материалом и разными доменами ссылок OUTMAX. Галочка «Создать локальную папку с изображениями» формирует в ZIP готовую для загрузки в корень сайта папку `image/<название статьи>` и заменяет редакционные изображения в HTML на пути `/image/<название статьи>/...`; товарные фотографии не копируются. Итоговый HTML рассчитан на ограниченный редактор админки: всё оформление записывается в атрибуты `style`, внешний CSS и классы не требуются, а неподдерживаемые `loading`, `decoding`, `role`, `aria-*`, `data-*` и `tabindex` удаляются. Изображения OUTMAX используют обычный прямой `src`. Внутренние якоря и ссылки на сторонние сайты не изменяются.

Адаптация меняет структуру и оформление, сохраняя исходный текст и ссылки. Редактору всё равно нужно проверить факты, цены, акции и alt изображений перед публикацией.

Текст редактируется прямо на холсте. Выпадающий список «Стиль текста H» превращает текущий блок в обычный текст или заголовок H1–H6; H7 сохраняется как оформленный абзац, потому что такого тега в HTML нет. Ссылка «HTML» открывает исходный код статьи для точной правки. Превью обновляется после каждого изменения. Для публикации можно передать HTML и соседнюю папку ресурсов; пути к картинкам в HTML относительные. Данные карточки товара и тексты статьи нужно проверить перед размещением.

### Пользователи, архивы и внешний предпросмотр (02.10.2026)

Серверная версия использует форму входа и четыре профиля: администратор Иван Радыгин, Иван Некрут (`ivan.nekrut`), Редактор 01 (`editor01`), Редактор 02 (`editor02`). Пароли редакторов генерируются автоматически при первом запуске и сохраняются между перезапусками. Существующие серверные логин/пароль администратора сохраняются. Актуальные данные входа рабочего сервера находятся в локальном `users-access.txt` (файл исключён из Git). При отсутствии серверных настроек начальные данные администратора находятся в `articles/_accounts/local-admin.txt`. Администратор видит и меняет имя, логин и пароль в меню имени → «Пользователи». Изменение учётных данных завершает старые сессии пользователя.

Личные статьи и изображения сохраняются в `articles/users/<id-профиля>/`. Меню «Приветствую, Имя» → «Все статьи» открывает архив обоих брендов с карточками, датами создания/изменения и количеством статей по месяцам создания. Кнопка удаления требует ответа «Да» или «Нет» и удаляет также материалы и ссылку предпросмотра.

Старые общие файлы в корне `articles/` не переносятся автоматически и не удаляются. В архиве кнопка «Открыть старые черновики» позволяет скопировать выбранную общую статью с материалами в свой профиль под новым идентификатором. Там же можно перенести черновик из прежнего IndexedDB этого браузера. Для черновиков ХАСЛ откройте раздел ХАСЛ на том устройстве, где сохраняли материал. Исходные локальные записи сохраняются. Имена владельцев старых общих статей неизвестны, поэтому пользователь сам выбирает свою статью.

В превью кнопка «Предпросмотр удалённо» сохраняет статью и создаёт постоянную случайную ссылку `/editor-api/public-preview/<токен>/`. Посетитель без входа видит только выбранную статью и её изображения, с переключателями «Десктоп» / «Телефон». По ссылке отображается последняя сохранённая версия. Для просмотра с другого устройства приложение должно быть опубликовано на доступном сервере; `127.0.0.1` доступен только на этом компьютере.

`articles/_accounts/` содержит SQLite с пользователями и ссылками и ключ шифрования паролей. Каталог нельзя публиковать как статические файлы. Для резервной копии сохраняйте весь `articles/`, включая `_accounts/` и `users/`. Приложение защищает эти пути; обратный прокси должен направлять `/login`, `/preview/`, `/editor-api/` и страницы редактора в обновлённое WSGI-приложение. Если перед приложением включена общая Basic Auth, её нужно заменить авторизацией приложения, иначе новые пользователи и посетители предпросмотра не смогут войти. Старые Basic Auth запросы с учётными данными пользователя остаются совместимыми для скриптов.

Локальный запуск `python app.py` теперь использует то же WSGI-приложение, что и сервер. Зависимости входа включены в `requirements.txt`. Статическая версия GitHub Pages сохраняет прежнее браузерное редактирование и не предоставляет серверные профили/ссылки. Серверный пакет собирается командой `python prepare_full_deploy.py python`; исходные статьи и учётные записи в пакет не включаются и должны храниться постоянно на сервере. Проверка: `python -m unittest test_accounts -v`.

### Модераторы и обновлённый интерфейс

Иван Некрут получил роль модератора. Модератор и администратор через меню профиля → «Архивы пользователей» могут выбрать любого пользователя, открыть его статью только для просмотра и сохранить самостоятельную копию в свой архив вместе с изображениями. Чужой оригинал нельзя изменить или удалить. Копия получает собственный идентификатор и даты; редактирование копии не влияет на оригинал. Обычный редактор видит только свой личный архив. Старый общий архив прежней версии доступен для переноса, как и раньше.

Администратор может добавлять пользователей с ролью редактора или модератора, менять роль существующего редактора и редактировать его имя, логин и пароль. Если при добавлении пароль не заполнен, сервер генерирует его автоматически и показывает данные входа. Кнопка «Сгенерировать пароль» доступна и при редактировании. В списке пользователей пароль раскрывается кнопкой глаза. Обновление базы добавляет роли без сброса существующих паролей, файлов и сессий; последующие перезапуски не отменяют изменения ролей, сделанные администратором.

Окна и формы используют единые отступы, SVG-иконки и состояния фокуса; предусмотрены мобильные экраны и уменьшение движения. Файловые поля для импорта снова скрыты и открываются соответствующими кнопками. Оформление экспортируемых статей и существующие инструменты редактирования сохранены.
