# Изолированный стенд Tiptap — блочная модель

Серверная версия: [новый редактор Tiptap](https://news.outmax-office.ru/tiptap/), вход под существующим аккаунтом. Ссылка есть в меню редакторов OUTMAX/ХАСЛ. Подключены серверное автосохранение, личный архив, история и конфликты. Контракт и проверки — [серверная интеграция](../../docs/TIPTAP_SERVER_SYNC_2026-10-07.md).

Локальный preview на 8878 проверяет сохранность HTML без записи на сервер. WSGI/VPS подключает аккаунты и API; старые статьи меняются только после явного открытия и редактирования. Результаты и зависимости находятся в игнорируемой `release/`; исходники и lockfile остаются в проекте для другого компьютера.

## Запуск из корня проекта

```powershell
New-Item -ItemType Directory -Path release/tiptap-check -Force | Out-Null
Copy-Item experiments/tiptap-editor/package.json release/tiptap-check/package.json
Copy-Item experiments/tiptap-editor/package-lock.json release/tiptap-check/package-lock.json
npm ci --prefix release/tiptap-check --no-audit --no-fund
node experiments/tiptap-editor/build-source.cjs
python experiments/tiptap-editor/serve.py
```

Открыть http://127.0.0.1:8878. Сервер слушает только localhost и отдаёт конкретные файлы стенда и ресурсы публикационных пакетов. Черновики, ключи, базы и служебные файлы через него недоступны.

Для локальной проверки через WSGI: `python experiments/tiptap-editor/package_server.py`, `python tests/ui_test_server.py`, загрузка медиа через `deploy_vps.upload_tiptap_media`, затем `node tests/tiptap-server-check.cjs`. Для VPS достаточно `python deploy_vps.py`: сборка и публикация выполняются автоматически.

Компактный `release/tiptap-prototype/server.zip` содержит код/CSS, контрольные HTML, оба публикационных body и манифест ресурсов. Изображения (включая responsive source) находятся в `media.zip` и загружаются отдельно, без изменения исходных байтов, фрагментами 256 КБ. Администратор может загрузить только зарегистрированные манифестом SHA-256; каждый фрагмент и завершённый файл проверяются, запись атомарная. На сервере неизменяемые файлы хранятся в `articles/_tiptap_media/`. Такой способ учитывает размерный предел SSH-deployer.

VPS-сборщик встраивает компактный пакет в `wsgi_app.py`; новый маршрут защищён общим входом, чтение разрешено только по точным именам пакета/манифеста. Приватные базы, ключи и локальные черновики не включаются. JSON/HTML сохраняют оригинальные пути медиа; только отображение редактора разрешает /components/ по домену выбранного бренда. Учётные данные не входят в клиентский пакет.

Нужны публикационные пакеты:

- `OUTMAX/OUTMAX_TOP10_ZIMA_2027_PUBLICATION_PACK_V2_1/`
- `ХАСЛ/HASL_TOP10_OSEN_2026_PUBLICATION_PACK_V4_4/`

Они не все переносятся через Git; копировать отдельно. `fixture.html` — переносимый контрольный материал с каждым видом блока. Для проверки локальных черновиков скрипт берёт самый большой body каждого бренда из `articles/`; при отсутствии локальных черновиков эти два кейса пропускаются и не считаются проверенными.

## Архитектура и границы

`block-schema.cjs` содержит блочные sectionBlock, productBlock, tocBlock, galleryBlock, accentBlock, ratingBlock, ctaBlock и htmlBlock. Абзацы и заголовки — настоящие textblock; текстовое форматирование — mark с сохранённой цепочкой HTML-обёрток. Списки используют нативные bulletList/orderedList/listItem, таблицы — Table/TableRow/TableCell/TableHeader. Стили, якоря, фотографии, атрибуты, исходные table-группы и отступы HTML хранятся явно. Неизвестный тег отменяет импорт вместо молчаливого удаления; запрещённые элементы/атрибуты удаляются с отчётом. JSON проверяется до отображения; ошибочный файл оставляет текущую статью открытой.

Включены Enter, Shift+Enter, жирный/курсив, H1–H6/обычный текст, вставка HTML/plain text и добавление/удаление строк/столбцов. Новый заголовок получает якорь; разделение блоков не дублирует block/inline id. Стрелки оглавления — защищённые атомы, Ctrl+A внутри подписи выбирает её текст. Технические пробелы между блоками остаются в экспортных метаданных, а редактор использует white-space:pre-wrap. Для прямого inline-текста контейнеров используются прозрачные абзацы; при разделении новый абзац получает обычный p. Это сохраняет старый HTML при полноценной блочной структуре документа.

JSON v2 (`brand-block-prototype-v2`) сохраняется и повторно открывается. JSON прежнего стенда v1 преобразуется через проверенный HTML в новую модель с явным сообщением. Бренд файла применяется при открытии. Рабочие JSON, documentId/revision/products и серверные сохранения пока не подключены.

**Для экспорта вызывать `exportHTML`, а не `Editor.getHTML()`.** Собственный сериализатор восстанавливает прозрачные абзацы, исходные mark-обёртки, thead/tbody/tfoot, caption и colgroup. Editor.getHTML предназначен для внутреннего представления стенда и содержит технические обёртки. Табличные команды сохраняют принадлежность новых строк группе. Caption/colgroup и часть оформления групп пока представлены метаданными и не полностью отражаются внутри contenteditable; экспорт их сохраняет.

## Настройки блоков

В списке «Настройки блока» выбрать товар, таблицу, галерею или акцент. Блок подсвечивается в редакторе; на desktop панель расположена справа, на телефоне — над статьёй с собственной прокруткой. «Открыть контрольные блоки» загружает синтетический материал, оставляя публикационные пакеты неизменными.

- Товар: название с сохранением стрелки, ссылка, текущая цена, фон и отступы. Размеры/свойства и оценки можно редактировать на холсте; каталожный API и structured products пока не подключены. Цены определяются из текущего HTML, а не запрашиваются заново на сайте.
- Сравнение: размер/цвет/фон/регистр заголовков, размеры/кадрирование/позиция/скругление фото, видимость и выбор фотографии товара, добавление/удаление товаров из карточек статьи, показатели и их порядок, сортировка. Автоматические значения доступны для цены, размеров и явных свойств; ручные значения сохраняются до явного «Обновить значения из карточек». Неоднозначная связь со строкой или отсутствующие данные отменяют обновление. Более сложные источники production-сравнения, например отдельное именованное свойство/наличие/старая цена, пока сохраняются как исходная настройка, без автоматического обновления.
- Галерея: лента/сетка, промежутки, высота, crop/позиция, адреса и alt, добавление/удаление/порядок фото. Если структура содержит подписи или несколько фото в одном вложенном элементе, структурные операции отключены; текст и вложения сохраняются. Замена picture/srcset пока блокируется явно. Загрузка локальных файлов ещё не реализована; вводятся адреса доступных ресурсов.
- Акцент: линия/рамка/заливка, цвета и интенсивность по общей логике `editor-styling.js`; «Фирменное» восстанавливает импортированные style/class, включая повторное открытие JSON.

`block-panels.cjs` работает с JSON выбранного узла, не правит contenteditable DOM. «Применить» — отдельный шаг undo; другие блоки не заменяются. Если выбранный блок изменён после открытия панели, применение отменяется. «Перечитать настройки» загружает текущие значения и сбрасывает неприменённые поля. Ошибки URL, значений и структуры не меняют документ. Техническая подсветка не включается в экспорт.

Проверка панелей: `tests/tiptap-panels-check.cjs`. Отчёт, отредактированный JSON/HTML и снимки: `release/tiptap-prototype/results-panels/`; переносимый отчёт — `docs/tiptap-validation/panels-report-2026-10-07.json`. На реальных пакетах проверены изменения/undo товаров, галерей и сравнения; на контрольном материале — значения, фото, строки/показатели, сортировка, восстановление акцента, ошибочные/устаревшие настройки и JSON reopen. Внешние изображения отключены в тестах. Это ещё не полный паритет всех production-инструментов.

Контроль DOM сравнивает все элементы, текстовые узлы, атрибуты и CSSOM-декларации с приоритетом important. Комментарии HTML не входят в сравнение. Проверены оба публикационных пакета, по одному локальному черновику бренда и контрольный материал; JSON/правка/undo/reimport, разделение вложенных списков и таблица с rowspan/colspan/caption/colgroup. Browser-проверки подтверждают Enter, Shift+Enter, пробелы, положение курсора, H2, табличные команды/undo, защиту TOC и открытие v1/v2. Clipboard-события синтетические, фрагменты Word/Google Docs контрольные: они не заменяют тестирование настоящих сложных документов, изображений в буфере и системного IME.

Отдельная browser-проверка сравнивает геометрию и ключевые computed styles **экспортированного** HTML с оригиналом на 1280/375 px, а не доказывает полное совпадение внутри contenteditable или работу экранной клавиатуры телефона.

Python-проверка вызывает реальные `export_archive`/`export_body` для RU/COM и сравнивает результат до/после стенда: HTML DOM, список ZIP и SHA-256 локальных медиа. Это проверка отсутствия новых потерь; она не подтверждает полноту исходных пакетов. В выбранных локальных черновиках скопировано 0 медиа; перенос их исходных файлов ещё требуется проверить. Browser adminBody, реальный ZIP-импорт, CMS, внешние фото и srcset-комплектность остаются отдельными критериями.

Следующий шаг: интегрировать настоящие browser adminBody/HTML/ZIP-импорт и полный набор локальных ресурсов, затем закрывать оставшиеся настройки до production-паритета. Остались настоящие Word/Docs paste, IME/телефон, производительность длинных статей, привязки обсуждений и откат. Не подключать этот стенд к production-сохранению и не деплоить вместо редактора до закрытия критериев.

## HTML/ZIP и ресурсы — первый шаг полного цикла

«Открыть файл» принимает HTML, JSON v1/v2/старого редактора и ZIP. При нескольких HTML появляется выбор страницы. Локальные PNG/JPEG/WebP/GIF загружаются в память и отображаются через blob-URL; модель сохраняет исходные src/srcset. ZIP содержит document.json, HTML и исходные изображения по прежним именам. С локальными файлами «Сохранить файл» создаёт ZIP, без них — JSON. JSON отдельно не переносит бинарные файлы.

Стили HTML сохраняются отдельно от модели, ограничиваются областью статьи и возвращаются в HTML/ZIP, включая @media. Внешние CSS, URL в CSS, font-face и неподдержанные правила отражаются в предупреждениях и пока не входят в доказанный цикл сохранности. Удалённые фото не скачиваются. Пределы ZIP: 64 МБ на входе, 96 МБ распакованного размера, 1500 файлов и 12 МБ на изображение; опасные пути отклоняются.

«HTML для CMS» использует production adminBody, CSS-переменные и восстановление TOC из editor.js: build-source.cjs извлекает реализацию в генерируемый production-admin.cjs. Проверено совпадение с рабочим редактором локального тестового сервера для обоих брендов. Финальная CMS-упаковка с ресурсами, RU/COM и полный импорт через production Python API ещё не закрыты.

На реальных ZIP OUTMAX/ХАСЛ сохранены DOM, пути и SHA-256 7/9 изображений, включая дополнительные ресурсы; видимые локальные img — 5/6, responsive source переносится. Контрольные тесты проверяют выбор страницы, CSS-изоляцию, srcset, ZIP reopen и ошибочный ZIP. Отчёты — docs/tiptap-validation/file-io-report-2026-10-07.json и real-file-io-report-2026-10-07.json. Серверное автосохранение/история подключены; см. отдельный протокол интеграции.
