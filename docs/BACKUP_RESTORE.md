# Резервное копирование и восстановление

Добавлено 7 октября 2026. Утилита `backup_project.py` работает локально и не отправляет данные в облако.

Результат фактического восстановления локального проекта: [BACKUP_DRILL_2026-10-07.md](BACKUP_DRILL_2026-10-07.md).

## Что входит в копию

- Код приложения, документация, тесты и сохранённые skills.
- Весь articles/: личные/старые черновики, email-проекты, медиа, история, журнал сохранений, опубликованные email-изображения и настройки.
- База пользователей с ролями, обсуждениями и preview-токенами; ключ шифрования аккаунтов сохраняется вместе с ней.
- Файловые настройки .env, .notisend.txt, notisend.txt, deploy_settings.py и два используемых конфигурационных файла из release/, если они существуют.
- С флагом --include-materials: исходные публикационные пакеты OUTMAX/ и ХАСЛ/.

Не включаются Git-история, SSH-ключи .deploy/, Python/Node-зависимости, прочие файлы release/, переменные окружения и IndexedDB браузера. Зависимости устанавливаются на новом компьютере по requirements и lockfile; переменные окружения сервера задаются отдельно. Несохранённые браузерные черновики сначала сохранить на сервере или экспортировать в ZIP.

Архив содержит приватные документы и данные доступа. Хранить его вне публичного сайта и репозитория; backups/ и ZIP исключены из Git. Копия на том же диске защищает от ошибочных правок, но для защиты от потери диска нужно перенести архив на другой носитель.

## Создание

Остановить все процессы редактора, работающие с этим каталогом: локальный Python, WSGI/службу и фоновые задания записи. Закрытие вкладки не останавливает сервер. На VPS выполнять команду в его каталоге, а не создавать локальную копию в надежде получить серверные статьи.

```powershell
python backup_project.py create --stopped --include-materials
```

--stopped подтверждает остановку; утилита не останавливает процессы сама. Создаётся новый ZIP в backups/ с уникальным именем. Можно задать --output и --project. Для меньшей копии без исходных публикационных пакетов убрать --include-materials.

SQLite копируется через штатный backup API; затем выполняется integrity_check. Для каждого файла записываются размер и SHA-256. Если состав, размер или время изменения исходников меняются во время копирования, операция отменяется. Эта проверка дополняет требование остановки, а не гарантирует согласованную копию работающего сервера.

## Проверка архива

```powershell
python backup_project.py verify backups/ИМЯ_КОПИИ.zip
```

Проверяются список файлов, контрольные суммы, CRC ZIP и SQLite. SHA-256 всего архива печатается при создании: его можно сохранить отдельно и сверить после переноса. Это проверка целостности, не цифровая подпись или шифрование.

## Восстановление в новую папку

```powershell
python backup_project.py restore backups/ИМЯ_КОПИИ.zip --destination E:/Восстановленный-редактор
```

Папка назначения должна отсутствовать. Существующий проект не удаляется и не перезаписывается. Архив сначала проверяется, распаковывается во временную папку с повторной проверкой SHA-256, затем каталог переименовывается в назначение. Опасные пути и ссылки в архиве отклоняются.

После восстановления:

1. Установить Python-зависимости: python -m pip install -r requirements.txt; для серверного запуска использовать requirements-server.txt.
2. Восстановить внешние переменные окружения и конфигурацию службы/прокси, если это сервер.
3. Запустить редактор из новой папки на свободном локальном порту: `$env:OUTMAX_START_PATH='/'`; python app.py использует 8765, поэтому прежний сервер сначала остановить. Не запускать две копии на одном порту.
4. Проверить вход, роли, статьи обоих брендов, историю/изображения, обсуждения и HTML/ZIP-экспорт. Не отправлять тестовые email при проверке копии рабочих данных.
5. Только после проверки переключать рабочую службу на восстановленный каталог; старую папку сохранить для отката. DNS, VPS и внешние сервисы утилита не меняет.

## Проверки разработчика

```powershell
python -m unittest test_backup_project -v
```

Проверены: повреждённый ZIP/контрольная сумма, выход за каталог, запрет перезаписи, изменение источников во время копирования. Полный изолированный сценарий восстанавливает аккаунт и ключ, вход пользователя, две версии, обсуждение и preview-токен, старую фотографию и ZIP-экспорт.

Периодический запуск и автоматическое удаление старых архивов пока не настроены. Срок хранения и место второй копии нужно выбрать отдельно; утилита не удаляет резервные копии автоматически.
