# Серверное подключение Tiptap

Новый редактор: https://news.outmax-office.ru/tiptap/. Вход и личный архив общие с OUTMAX/ХАСЛ. Старые статьи можно открыть через «Мои статьи»; статьи с editorEngine=tiptap из прежнего архива направляются в Tiptap.

VPS обновлён 7 октября 2026 в 15:04:01 UTC. После публикации пройдены server-sync-check (15:05:42 UTC) и file-io-check (15:05:20 UTC) на https://news.outmax-office.ru. Текст/JSON, история/фото/CSS и конфликт проверялись на созданных тестом статьях.

Подключены название, создание статьи, ручное и автоматическое сохранение, архив, история, скачивание исторического JSON и восстановление новым сохранением. Канонические данные — модель v2, fileMeta (CSS, пути ресурсов) и карта serverAssets; HTML для просмотра формируется тем же adminBody, что используется рабочим редактором. После редактирования в прежнем HTML-движке устаревшая модель Tiptap удаляется.

Хранение использует существующие atomic_write, SQLite-журнал, expectedRevision/documentId и неизменяемый requestId для повтора потерянного ответа. CSS-правки тоже создают версии. Изображения загружаются без перекодирования в личный `_tiptap_assets/<SHA256>.<ext>`; сервер проверяет хеш и предел 12 МБ. Уже загруженные ресурсы кешируются в текущей сессии. Копирование администратором между архивами переносит нужные файлы, не открывая чужие ресурсы остальным пользователям.

IndexedDB хранит последнее состояние и неотвеченный запрос отдельно для пользователя, документа и вкладки. После загрузки страницы и проверки аккаунта восстанавливаются несохранённые правки. При сбое повтор идёт с увеличивающимся интервалом до 30 секунд; конфликт 409 останавливает запись. Предлагаются отдельная копия, скачивание ZIP и явная замена серверной версией. Полностью автономная загрузка приложения без сети пока не реализована: это не PWA.

Дублирование вкладки проверено: BroadcastChannel выявляет скопированный sessionStorage ID и выделяет отдельную очередь; копия исходного локального состояния получает собственные запросы. Во время загрузки серверного документа ввод отключён. Старые статьи загружают локальные фотографии из личного архива, после правки переносят их без перекодирования в immutable-хранилище; метаданные товаров сохраняются в fileMeta.legacyProducts.

Скачанный исторический JSON можно повторно открыть на серверной странице: разрешены только ссылки `/articles/_tiptap_assets/<SHA256>.<ext>` текущего аккаунта, фотографии загружаются перед заменой документа. Для переноса файлов без доступа к аккаунту используйте ZIP с фото.

При смене документа сначала завершается сохранение. Сбой/конфликт блокирует переход. Бренд и ID отражаются в адресе, чтобы перезагрузка не переключала материал. Примеры открываются как отдельные статьи. Зарегистрированные фотографии примеров доступны через неизменяемые серверные ресурсы; ZIP добавляет их исходные байты. Загруженные пользователем фотографии хранятся приватно.

## Проверки

- `python -m unittest test_tiptap_storage -q`: приватность, SHA-256, повторы, CSS-версия, восстановление native JSON, перенос ресурсов между архивами, опасный HTML, переход к старому движку.
- `node tests/tiptap-sync-check.cjs`: две вкладки/409, отдельная копия, новая ревизия восстановления, фото и CSS после reload/restore, потерянный ответ, очередь после перезагрузки, реальные статьи обоих брендов, мобильная ширина и анонимный доступ. Для VPS: `$env:TIPTAP_SYNC_BASE='https://news.outmax-office.ru'`.
- Существующие проверки storage/history/accounts, native schema, HTML/ZIP, UI 1440/1280/768/375 также проходят.

Отчёт: [server-sync-report-2026-10-07.json](tiptap-validation/server-sync-report-2026-10-07.json). Браузерные тесты создают свои статьи и удаляют их после проверки; исходные пользовательские материалы не редактируются.

## Интерфейс и skills

Использованы [emil-design-eng](https://github.com/emilkowalski/skills) и [playwright](https://github.com/openai/skills/tree/main/skills/.curated/playwright). Установка и перенос skills описаны в START_HERE_CODEX.md.

| Before | After | Why |
| --- | --- | --- |
| Только скачивание файла | Отдельная строка названия и серверных действий, заметная «Сохранить» | Видно, где находится материал и как вернуться к нему |
| Не было статуса серверных правок | Статусы сохранения, восстановления, повторов и конфликта | Пользователь видит результат записи |
| Конфликт не имел действий | Три явных кнопки рядом с объяснением | Локальные правки остаются доступными |
| Перезагрузка могла открыть другой бренд | Адрес содержит ID и бренд | Открывается тот же документ |
| Служебные img-разделители внутри picture могли показывать srcset-фото | Служебным изображениям заданы нулевые размеры | Сохраняется caret-guard, фото не дублируется в редакторе |

## Следующий этап

Довести паритет инструментов: семейство/размер/цвет текста и история цветов, ссылки, создание и обновление оглавления, вставка брендовых блоков из библиотеки и каталога. Затем реальные Word/Docs-вставки, IME/телефон, редакторские права и обсуждения. Полную миграцию главной страницы выполнять после этих проверок и проверки экспорта. Текущая интеграция серверного сохранения не подтверждает завершение всего паритета.
